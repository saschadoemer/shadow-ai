# Architecture Decision Records

Short, one per decision, recording the **why**. An ADR holds what nobody can reconstruct from the
code: which options were on the table, why the others lost, and what would reopen the question.

Numbered sequentially from 0001. Never edit an accepted ADR to change its decision — write a new
one and mark the old one superseded. Use `0000-template.md`.

An ADR is written when the decision is made, not later. A decision that is still moving is not
ready for an ADR; it stays in the feature spec until it settles.
